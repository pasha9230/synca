# Tires Sync: правила работы

Система берёт выгрузку поставщика шин, считает цены, собирает фиды Авито для нескольких аккаунтов, читает чаты и ведёт заказы. Python, sqlite, панель на Flask, таймеры systemd.

**Репозиторий открытый: всё, что ты пишешь сюда, видят все.**

## Экономия лимита
- Модель Sonnet, средний уровень рассуждений. Opus только по просьбе человека или для независимого ревью критичной правки.
- Одна сессия на задачу. Задача закрыта: `/clear`.
- Файлы целиком не читать: `rg` по имени, затем `Read` с `offset`/`limit`. После правки не перечитывать.
- Субагентов не запускать, кроме независимого ревью.

## Как начинать
1. Поставь задачу в общий список задач (ссылку даёт владелец).
2. Заведи отдельную ветку от свежего `origin/master` (если тимлид не назвал другую): `git fetch origin`, `git switch -c <ветка> origin/master`.
3. Общий таймлайн: ещё не сделан, пока ничего писать не нужно.

## Порядок работы
1. Понять код: нужное место, его тесты, кто его вызывает. Искать причину, а не глушить симптом.
2. Тест, который покажет нужное поведение.
3. Код: наименьшая правка, закрывающая задачу. Находки по ходу: отдельной задачей, не «заодно».
4. Проверка: точечные тесты, просмотр своего диффа.
5. Отчёт простым русским: что изменилось, чем проверено (команда и результат), что не проверено, что нужно от человека. Не писать «готово» без прогона.

Один смысл: один коммит. Тест не ослаблять и не удалять ради зелёного прогона: если поведение изменилось осознанно, объясни это и поправь тест. Решения, записанные в `docs/feed-rules.md`, в коде и в тестах, не пересматривать без слова владельца.

## Тесты
```bash
python -m pip install -e ".[dev]"
python -m pytest tests/test_feed_check.py -q --tb=short
```
Локально только точечно (файл или `-k`). Полный прогон идёт на GitHub при push ветки: проверка `pytest`. Панель работает на Linux и macOS: на Windows нет `fcntl`, часть модулей не импортируется. Скрипты с кириллицей запускать из файла, а не из `-c`.

## Критичное: только через план и согласие владельца
- всё, что уходит на Авито: Id, цены, телефон, состав, названия, фото, теги, порог остатка, снятие;
- цены и деньги: наценки, продажи, сторно, заказы;
- миграции базы, удаление данных, бэкап и восстановление, настройки;
- сообщения клиентам;
- вход, права, секреты и ключи;
- выкладка и проверки: `deploy/`, `.github/`, вливание в `master`.

Порядок: разобраться без правок → план «было → стало» и строка «Откат» → согласие владельца → тесты → код → полный прогон → независимое ревью свежим субагентом (Opus, если доступен). Сомневаешься, критично ли: считай критичным.

Новое правило проверки фида: только по слову владельца; порядок в `docs/feed-check-rules.md`.

Что чаще всего ломается в фиде: значения другого аккаунта (телефон, адрес, Id); новый Id у живого объявления (Авито блокирует как «Повторное размещение», это не замена); ручное «вкл» не снижает порог остатка.

## Запрещено
- `git push --force`, `git reset --hard`, `git clean`, `rm -rf`, прямой push в `master`.
- Читать ключи и `.env`. Нужен ключ: спроси владельца.
- Боевая база и сервер недоступны и не нужны. Запись в Авито и сообщения клиентам из разработки не выполнять.
- Класть в репозиторий настоящие телефоны, домены, ключи, имена клиентов и сотрудников, личные почты и локальные пути. В примерах и тестах только заглушки: `example.com`, выдуманные номера и имена.

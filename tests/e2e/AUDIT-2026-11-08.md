# Аудит экранов панели, 2026-11-08 (Playwright, «Новый вид» включён)

**Запуск одной командой** (из корня репозитория, после `python -m pip install -e ".[dev]"`):

```bash
python tests/e2e/crawl.py /tmp/e2e-shots && python tests/e2e/summarize.py /tmp/e2e-shots
```

Нужен Chromium: в облачной сессии берётся `/opt/pw-browsers/chromium`, иначе `python -m playwright install chromium` или `E2E_CHROMIUM=<путь>`.
Быстрее по ролям параллельно: `E2E_ROLES=owner python tests/e2e/crawl.py /tmp/e2e-shots` (по процессу на роль; `summarize.py` склеит `report-*.json`).
Поднять панель руками и посмотреть глазами: `python tests/e2e/serve.py /tmp/e2e-panel 8765` → http://127.0.0.1:8765, владелец: пустой логин и `e2e-owner-1`, остальные: `partner1`, `office1`, `viewer1`, `point1`, `point2`, `client1` с паролем `e2e-password-1`.

## Что сделано

- `tests/e2e/seed.py` — временная база с выдуманными данными через код панели: 2 аккаунта Авито, 3 точки, роли владелец / партнёр / менеджер чатов (офис) / наблюдатель / 2 точки / клиент, 8 чатов, 15 заказов во всех этапах (новый, переговоры, оформлен в WebMIM, номер перемещения, едет, на точке, резерв день 3 и день 7, ОТХ, на возврат, согласовано на возврат, вернули поставщику, выдан, отменён до точки, разбит на два заказа WebMIM), 3 открытых красных уведомления и одно закрытое, задачи. «Новый вид» включён у всех трёх групп. Этап «Ожидает наличие» не засеян (нужны «что нужно клиенту»), колонка пустая.
- `tests/e2e/serve.py` — панель на этой базе; все внешние клиенты (Авито, WebMIM, Telegram, VK, Google-таблица, 4 Точки, загрузка фото, фоновые запуски) — заглушки, которые отказывают и считаются; сокеты и DNS только на localhost. **За весь обход ни одного внешнего вызова.**
- `tests/e2e/crawl.py` — вход каждой ролью через форму входа, все пункты меню и вкладки на них, все 15 карточек заказов (точке — свои плюс одна чужая), окна `data-open-modal` (в том числе из меню «Ещё»), на 1280×800 и 375×812 (телефон эмулируется с `is_mobile`, т. е. учитывает `<meta viewport>`). Только GET и клики, открывающие окна; форм не отправляет, кроме входа. Проверки: код ответа, ответы ≥400 у подзапросов, ошибки консоли, горизонтальное переполнение, обрезанный текст, наложение кнопок, цвета и шрифты старой палитры под `body.ui-new`, размеры шрифта вне шкалы, повторы текста, битые внутренние ссылки.
- `tests/e2e/test_e2e_seed.py` — быстрый тест без браузера (идёт в обычном `pytest`): в базе есть все этапы, каждая роль входит, внешних вызовов нет.
- Playwright `1.58.0` добавлен в extra `dev` (`pyproject.toml`). **`pyproject.toml` в `.github/CODEOWNERS`: вливание закроется до одобрения владельца.** Отдельной задачи CI для обхода нет.

Итог прогона: 694 экрана, 0 ответов 5xx, 0 внешних вызовов, 1 битая ссылка, ~4 минуты (6 процессов). В `tests/e2e/shots/` (JPEG, только выдуманные данные, ≈23 МБ): все снимки, на которые ссылается отчёт, и все экраны владельца, точки и клиента на обеих ширинах. Полный набор всех ролей с окнами (≈57 МБ) получается командой выше. Имя файла: `<роль>__<ширина>__<адрес>.jpg`.

Чего аудит не покрыл: окно «Отмена или возврат» у части карточек не открылось за 3 с (меню «Ещё», нестабильно), «Работать как точка» у владельца не обходился, вкладки внутри вкладок и фильтры каталога (сортировки, размер страницы) снимались по одному разу. Проверка «повторы» и «вне раздела» — моё суждение по снимкам, не автомат.

## Настоящие ошибки (сначала они)

**Б1. Кнопка «Включить» на «Главной» у офиса и наблюдателя ведёт на закрытую страницу.** Роли «Менеджер чатов» и «Наблюдатель» видят в «Требует внимания» строки «Публикация фида выключена» с кнопкой «Включить» → `/connections/avito`, раздела «Настройка» у них нет (403). Там же весь блок «Готовность к публикации» с кнопками «Открыть» в настройки. 1280 и 375. `office1__1280__home.jpg`, `viewer1__1280__home.jpg`. Предложение: строки про фид и готовность показывать только ролям с «Настройкой»/правом «публиковать». Риск: низкий (кнопка не пишет, но вводит в заблуждение).

**Б2. «Открыть образец» у «4 Точек» — ссылка на 404.** `/connections/tochki` всегда показывает ссылку на `/connections/tochki/sample`, а без сохранённого образца маршрут отвечает 404 (`routes_connections.py`, `connections_tochki_sample`). Владелец и партнёр. `owner__1280__connections_tochki.jpg`. Предложение: показывать ссылку, только когда файл образца есть. Риск: низкий.

**Б3. Наблюдатель и офис видят форму «Сохранить список» в «Генерации».** В `photos_review.html` форма `/photos/priority` не обёрнута в `can_post(...)`, в отличие от «Сгенерировать» рядом. Наблюдатель видит кнопку записи и строку расходов «Потрачено сегодня $0.00 из $5.00». `viewer1__1280__photos_review_tab_queue.jpg`. Предложение: обернуть форму в `can_post`, расходы показывать владельцу. Риск: низкий (запись сервер, вероятно, отклонит; не проверял, формы не отправлялись).

**Б4. Точке на телефоне «Уведомления» и «Свой пароль» открываются компьютерной версией.** У этих страниц `<meta viewport width=1280>`: на 375 точка видит уменьшенный офисный экран с боковым меню и офисной строкой поиска, без нижнего меню точки. `point1__375__alerts.jpg`. Так же выглядит страница 403 при открытии чужого заказа (`point1__375__orders_4.jpg`). Предложение: для роли точки отдавать этим страницам мобильную раскладку `point2`. Риск: низкий.

**Б5. Карточка заказа и доска на телефоне шире экрана.** У `/orders` и `/orders/<id>` `width=device-width`, но раскладка не уже 1000 px: телефон уменьшает страницу до 1000 px. В средней колонке карточки на этой ширине подписи формы «Задачи по заказу» налезают друг на друга («Текст» на «Кому», «Комментарий» обрезан). `owner__375__orders_8.jpg`, `owner__375__orders.jpg`. Остальные офисные страницы (`width=1280`) — уменьшенная компьютерная версия: 45 страниц у владельца, 18 у офиса и наблюдателя. Предложение: решить, офис на телефоне — «только компьютер» (тогда и заказам `width=1280`) или мобильная раскладка карточки в одну колонку. Риск: низкий.

**Б6. «На ОТХ» шире даже компьютерной ширины.** На 375 таблица даёт ширину 1349 px при `width=1280`: горизонтальная прокрутка. `owner__375__oth.jpg`. Предложение: перенос в колонке «Заказ» / сократить колонки (см. п. 13). Риск: низкий.

**Б7. Магазин клиента: ошибки CSP в консоли на каждой странице.** `/shop*` отдаёт CSP `default-src 'none'` без `font-src`, а стили всё ещё тянут Inter / Instrument Sans / JetBrains Mono — браузер их блокирует, в консоли 5 ошибок на экран. `client1__1280__shop.jpg`. Предложение: под «Новым видом» не ссылаться на старые шрифты в клиентских стилях или разрешить `font-src 'self'`. Риск: низкий (касается заголовков безопасности: CSP — критичная зона, менять только с согласия владельца).

# План: продажи и надбавка точки по id точки (ветка point-id-sales)

## Было
- Продажа хранит точку только текстом: `sale.point` — название точки в момент продажи.
- Отчёт «Заказы по точкам» (`order_report.build`) группирует продажи по этому тексту, а надбавку за переданных клиентов
  отдаёт точке по её ТЕКУЩЕМУ названию (`order_handoff.point_id` → `point.name`).
- Переименовали точку → старые продажи в одной строке (старое имя), новые и надбавка — в другой. Деньги точки расходятся.
- Страница «Продажи» (разбивка «По точке», фильтр по точке) — тоже по тексту.

## Стало
- Новая колонка `sale.point_id INTEGER` (может быть пустой). Текст `sale.point` остаётся как история.
- Миграция в `store._migrate`: один раз, в одной транзакции — добавить колонку и заполнить её из `point.name`
  при точном совпадении названия. Повторный запуск ничего не делает (колонка уже есть).
- Обе записи продажи ставят `point_id`: из заказа — id точки заказа (`order_card.point_id`); ручная продажа — id точки
  с точно таким названием, иначе пусто.
- `sales.list_sales` отдаёт `point` = текущее название точки по id, а если точки по id нет (удалена, или id пуст) —
  сохранённый текст. Фильтр «точка» — по этому же показанному названию.
- Отчёт группирует продажи по id точки (без id — по тексту, как сегодня), надбавку — тоже по id. Переименованная точка
  — одна строка с текущим названием. Для непереименованных точек цифры те же, что сегодня (тест: тот же отчёт на тех же
  данных с точками и без них).
- Список точек в фильтре отчёта — показанные названия.

## Тесты (сначала красные на старом коде)
- миграция на старой схеме: колонка добавлена, заполнение по точному названию, второй запуск ничего не меняет;
- переименование точки → одна строка, итоги не изменились; надбавка в той же строке;
- продажа точки, которой больше нет → строка со старым текстовым названием;
- золотые цифры отчёта на общей базе — те же при заведённых точках.

## Откат
- Код: `git revert` коммитов ветки. Добавленная колонка `sale.point_id` остаётся в базе и просто не используется
  (старый код её не читает; INSERT старого кода её не заполняет — пусто допустимо).
- Данные: тимлид снимает копию базы перед выкладкой.

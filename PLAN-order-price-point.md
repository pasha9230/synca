# План: цена позиции по аккаунту обращения + «Точка» не слетает

## 1. Цена позиции (деньги, RED)

Было: все пути, которые сами ставят цену позиции заказа, считают её по первому аккаунту фида:
`order_offers.effective_settings` и `routes_economics._effective` берут `accounts[0]`.
Пути: заказ из чата (`routes_chats._position_provider` → `chat_deals._add_position`), «Добавить в заказ» в чате,
подсказки поиска позиции (`/orders/items/find`, JS кладёт цену подсказки в поле «Цена за шт.», и она уходит
как введённая вручную), «+»/«Сохранить» с позицией в карточке, новый заказ (форма и «Оформить заказ» из каталога).
Вторая ошибка: вызывающие передают уже «эффективные» настройки первого аккаунта, а `item_args` накладывает
поправку аккаунта второй раз.

Стало (уточнение тимлида 2026-10-26: опубликованная цена важнее пересчёта): цена = цена этой шины в последнем
опубликованном фиде аккаунта (`published_state`, то, что видел клиент); нет её (не публиковалась, зеркало) → цена, как её считает фид (`final_price` по правилам
`connections.effective_settings(аккаунт)`), поправка накладывается один раз. Аккаунт определяется так:
1. есть чат (заказ из чата, «Добавить в заказ» в чате) → аккаунт этого чата;
2. заказ: самый ранний привязанный чат → его аккаунт; нет чата → аккаунт Авито точки заказа; иначе основной;
3. новый заказ (ещё нет карточки): чат из поля «Чат Авито» → его аккаунт; иначе аккаунт точки из поля; иначе основной;
4. найденный аккаунт не в фиде (только чаты) → основной (первый аккаунт фида), как сейчас.
Подсказки получают тот же контекст (`order=`, `chat=`, поля формы), чтобы JS не подставлял чужую цену.
Цены уже добавленных позиций не меняются; цена, введённая руками, по-прежнему важнее.

## 2. «Точка» и другие поля слетают

Было: в карточке кнопка «+» отправляет всё окно на `/orders/<id>/items/add`, а тот добавляет только позицию:
выбранная точка, комментарий и любые другие поля окна молча теряются (воспроизведено тестом).
Стало: «+» окна карточки (форма прислала `was`) сохраняет поля так же, как «Сохранить», и добавляет позицию;
возврат на раздел «Позиции». Тесты: все поля новой формы и карточки после сохранения и повторного сохранения,
смена точки в существующем заказе, «+» после выбора точки.
